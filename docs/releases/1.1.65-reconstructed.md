## Executable exact-byte route

Use `.github/workflows/qualify-exact-jar-1.1.65.yml` and `tools/qualification/qualify_1_1_65.py`.
The separate repair-branch push route qualifies binary bytes only. It does **not** accept Minecraft terms, start a packaged server, expose CurseForge credentials, create a release/tag, merge code, or publish a JAR.

The workflow checks the pinned successful Build identity, makes two clean checkouts of the immutable runtime SHA, and builds each with separate Gradle homes and no persisted build cache. It then compares both JARs against the expected SHA-256 and each other, records the actual size, validates ZIP integrity/unique paths, embedded mod/dependency/version metadata, Java class compatibility, mixin resources, and byte-equal source notices. It rechecks live exact-source CI before the binary report succeeds.
Only JSON/text evidence is uploaded to Actions; runtime JARs remain ephemeral. A hash mismatch fails instead of rewriting the expectation. The tooling commit and runtime source commit are separate identities.

`BINARY_REPRODUCED` means two independently executed builds of the same source produced the checked bytes in this environment. It does not establish universal reproducibility, an independent reviewer, client gameplay or publication readiness.
