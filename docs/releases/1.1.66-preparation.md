## Cause and targeted correction

The existing exact-JAR qualification workflow and tool had source commit, source tree, version, Build run, and expected JAR digest hardcoded to 1.1.65. Its evidence artifact contained JSON/text only, so it could not qualify an explicit 1.1.66 candidate or provide the binary for byte review. The main Build workflow reports a digest but not a size.

This draft extends the existing qualification path with a strict candidate spec at `tools/qualification/iedctr-1.1.66.json`. It pins the exact runtime commit, version, successful Build run and attempt, mod ID, and the Build-log digest expectation. The tool validates that exact successful `main` push Build and clean source checkouts, rebuilds twice with separate Gradle homes and no build cache, validates embedded mod/version/dependency/license and notice metadata, inspects archive safety and class compatibility, computes each actual JAR's byte size and SHA-256, and requires both builds and the observed CI digest to match.

Only after those checks pass, the workflow stages the inspected JAR as a separate, 14-day GitHub Actions review artifact. That artifact contains only the runtime JAR. The text report states the measured size and digest. This qualification path has read-only repository and Actions permissions; it uses no CurseForge secret, does not install a server, and does not publish. A digest written in the spec is only an expectation: the job's computed JAR bytes must independently match it.

Qualification run [41359347817](https://github.com/emmanueltremblay9-stack/Immersive-Engineer-Decor-Controls-Tool-Reforged/actions/runs/41359347817) initially stopped before building because GitHub could not resolve the old pinned setup-python commit.
